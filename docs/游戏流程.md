## 流程总览

```text
开场：深夜的手机与断线
  → AkaneRei 登录回声 ECHOS
  → CASE 01 已读不回（N9Rtz / 事故夜时间线 + 录音净化）
  → CASE 02 已注销（LuvisDrug / 残留账号与平台犯罪链）

  → 注销：提交全部证据（已离线）/ 重新登录（循环）
```

游戏故意要求玩家按怀疑的关键词检索聊天记录，而不是按固定目录阅读。下文给出的是不漏证据的完美路线，不代表 UI 应把它显示成任务清单。

调查台账按「聊天对象」归并为四个章节。对应事实推导完成前，台账只显示对象名；完成后揭示章节名：`已读不回`、`已注销`、`冷备份`、`最后在线`。

对象名是入口词，不是全案目录。直接检索时，索引保持以下范围：

| 检索词 | 允许返回的最大范围 |
| --- | --- |
| `N9Rtz` | 会话（事故夜后空白）、资料卡；不提前返回事故夜录音 |

## 0. 开场与登录

1. 观看三段手机画面记忆：深夜群聊的欢笑刷屏、汐泊诺思分享歌单、与 N9Rtz 的语音通话界面。
2. 文案从日常过渡到「连接」的脆弱与意识错位，随后醒来。
3. 点击进入登录页：回声 ECHOS。
4. 使用账号密码登录：`AkaneRei` / `0408` 🔒（初始密码为事故日期后四位）。
5. 登录瞬间短暂飘红闪烁，随后进入正常的会话列表。
6. 全新存档首次进入首页后，先保持约 3 秒安静，再播放一次消息提示音并弹出初始信息窗（全员群的最新消息摘要）。继续游戏、刷新恢复和后续剧情消息不使用这段首次登录延迟。

验证点：

- 开场不是营销首页，第一屏就是演出。
- 开场、普通登录与结局使用忧伤阴郁的 D 小调主题。进入会话列表后不播放背景音乐，只保留消息提示音；玩家检索到「零信号」并收到检索行为告警后，才启用悬疑氛围曲（素材授权与参考项目同流程，来源记录于 `public/audio/SYSTEM_MUSIC_SOURCE.md` 同构文件）。「已注销」账号、身份侦测与零信号膨胀阶段改用惊悚氛围曲。音乐在首次用户操作后开始，静音偏好跨刷新保留。
- 播放语音或分轨时，背景音乐自动压低，不能遮蔽案件原始音频。
- 新证据实际写入调查台账时播放一次独立的低音确认提示；重复核验、刷新和恢复旧存档不得重复播放。
- 刷新在 hash 路由和本地存档允许的范围内恢复当前页面。
- 登录页/账号安全中心的 `遗忘`（清除本机数据）二次确认后清空全部进度回到初始状态。
- 未恢复 LuvisDrug 凭据之前，账号选择中不能直接使用残留账号。

## 4. CASE 04：最后在线（AkaneRei 自己）

### 4.1 账号来源复核

### 4.3 Aka-0 暗线（对应参考 CS-046）

玩家确认身份前，精确检索 `Aka-0` 不展示普通结果：系统先反复追加「没有找到完全匹配的记录」，逐层转入旧会话、冷备份、旧终端索引，随后所有结果与检索区被「正在输入…」与灰色波形覆盖。输入其他关键词即可中断演出。该彩蛋不写入证据，也不替玩家确认账号身份。

- 第一段：N9Rtz 事故夜通话质检回放
- 第二段：LuvisDrug 注销前最后的私信质检
- 第三段：汐泊诺思日常问候质检

隐藏复核页保留平台质检工作台的字段结构，但出现状态重影、字段错位、扫描线与灰色波形残影。演出保持可读，动画不得遮挡表单。只要求填写三项调查结论：

- Aka-0 是谁：`沈零`
- AkaneRei 账号状态：选择 `已死亡`

确认后再次精确检索 `Aka-0`，检索只返回《Aka-0 账号身份复核归档》。归档保存玩家的人工判断及其依据，不解释「同一意识」或循环机制。
